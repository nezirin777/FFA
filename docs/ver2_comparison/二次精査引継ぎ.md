# Ver2 / Ver3 比較台帳 二次精査引継ぎ

最終更新: 2026-08-30

## この作業の目的

一次比較で「一致」「意図的」「不具合を修正済み」とした記録を含め、Ver2・現行実装・過去の判断根拠を**台帳の全行について再確認する**。

目的はVer2へ機械的に合わせることではない。一次比較の見落とし、根拠のない「意図的」判定、後続変更による台帳と実装の不一致を見つけ、各差異をユーザー判断として信頼できる形で残すことである。

## 二次精査の厳守手順

1. 最初に対象の**台帳Markdownファイル名**を明示する。`.py` やテンプレートを先に単位として選ばない。
2. 対象台帳を先頭から最後まで読み、全見出し・全行を対象として扱う。既存の「確認済み」「現行維持」「意図的」は根拠ではなく再確認対象である。
3. 各行について、Ver2の該当箇所、現行の該当箇所、関連コミット・既存台帳記述を照合する。
4. 差異がある場合は、事実と影響を説明してユーザー判断を待つ。Ver2との差異だけを理由に変更しない。
5. ユーザーが決定した場合だけ実装を変更する。決定が現行維持ならコードは変更しない。
6. 決定後は必ず `tools/generate_ver2_comparison_checklists.py` を更新し、生成コマンドでMarkdown台帳を再生成する。生成済みMarkdownを直接の正本として編集しない。
7. 対象台帳の**全行**を終えた時だけ、このファイルの「二次精査完了台帳」へ台帳名・完了コミット・日付を追記する。それまでは次の台帳へ進まない。
8. コミットはユーザーが指示した時だけ行う。コミット前に `git diff --check` と必要な構文・生成確認を行う。

## 最近確定した判断（再確認時も根拠を確認すること）

- チャンピオン敗北時経験値は `min(相手Lv, 自分Lv × 10)` の現行バランスを維持する。
- レジェンドは最終クリア後に再挑戦可能。ただし称号が実際に上昇した初回だけ全体通知する。途中進行は街へ戻った時点でリセットする。
- 戦闘は速度・先攻後攻を導入せず、双方の成立した行動を同ターンに同時精算する。回復は最大HPまでで打ち止めてから同ターン被ダメージを適用する。
- 対人長期戦の瀕死時10倍補正はVer2互換として復元する。防御・上級職軽減の後、通常の回避判定に代えて適用する。
- 倉庫の接続元更新と装備交換順は現行仕様を維持する。破棄は共通確認モーダルを表示する。
- 防具・装飾品の売却時接続元ホストは更新しない現行仕様を維持する。
- 英雄ランキングは同じ記録値ならレベルが高い冒険者を上位にする。
- 私信機能と残存私信データは廃止する。

## 禁止事項

- 台帳ファイルを完了する前に、次の台帳や次のソースファイルへ移ること。
- 「Ver2と違う」だけで現行コードを変更すること。
- ユーザー判断なしに `意図的`、`現行維持`、`修正済み` を新規確定すること。
- 台帳更新を後回しにしてコード変更・コミットだけを先行させること。
